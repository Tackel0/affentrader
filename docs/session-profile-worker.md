# Background Session Volume Profile calculation

Collected profiles above 10,000 executions now run the same `buildSessionVolumeProfiles` calculation in a dedicated shared browser worker. Smaller profiles retain their immediate calculation path. The collector still observes and deduplicates live executions on the main thread; this change moves large model calculations, not all order-flow work, off that thread.

`SessionProfileJobs` serializes worker CPU work, keeps at most one queued snapshot per study and bounds the shared queue at 32 studies. Numeric time/price/quantity/side fields use a transferable Float64Array. Execution IDs have already been deduplicated; worker-local row IDs preserve that uniqueness. The actual simulated/exchange source flag is retained. Up to 16 exact session calendars are cached inside the worker. The generated public worker is rebuilt by the existing development/test/typecheck/build preparation chain.

The native descriptor permits one pending request per study. Ticks arriving during a calculation continue into the collector; a completed snapshot can be published before calculating the newer snapshot, avoiding starvation in active markets. While updating, the last completed profile remains tied to its own displayed execution count and UTC coverage, with an updating caption and loading status. First calculation shows a calculation notice. A mathematical settings change clears previous geometry; display-only settings reuse it. Suspension, disposal, market/native restart, Replay, explicit tape resets, source transitions and capacity failures invalidate late results. Worker errors and a 30-second timeout produce visible failure rather than silent synchronous fallback; hide/show retries. The 100,000-execution capacity still fails explicitly on the next unique execution.

Browser testing found an additional real upper-bound failure: passing 100,000 price arguments to `Math.min/max` exceeded the browser worker's call-stack limit even though the Node test passed. Session extrema now use a loop. This does not alter the profile mathematics and avoids large temporary mapped price arrays.

## Evidence

- **1,454 tests across 125 files passed**, including 13 new worker tests. Production build and TypeScript passed.
- Tests execute the shipped worker bundle and compare its complete model with synchronous batch output at 100,000 executions, a DST configuration and an explicit unsupported row count. Descriptor tests cover pending live updates, style/math edits, stale results across six lifecycle transitions, collection overflow during pending work and retry after worker failure. Scheduler tests cover transfer lists, coalescing, cancellation, timeout and events from a replaced worker.
- `node scripts/verify-session-profile-worker.mjs` serves a loopback-only, explicitly simulated native Vela fixture. It mounts the actual native descriptor, production worker and profile painter. Browser verification rendered exactly 100,000 executions and 100,000 volume. A response-counter click succeeded; animation frames continued. The first request settled in 129 ms with a largest observed frame gap of 49 ms, including fixture generation and main-thread collection. These are one local run's measurements, not a universal performance guarantee.
- Rapid row-size 1→4 settled at 4; unsupported rows showed an error; row size 2 recovered to the complete volume. Hide/show preserved all executions. Explicit source reset removed the profile and returned to collecting. No console warnings/errors were recorded in the fixture.
- The final production worker route returned HTTP 200 with the exact build-file SHA-256. The production BTC/5m workspace mounted a live SVP, then the temporary study was removed to restore the original EMA/Volume scene. Production console results are saved separately.

Evidence lives in `artifacts/session-profile-worker-*`: test/build logs, served-worker hash, native fixture DOM reports, screenshots and browser console reports. The fixture uses no exchange data and proves no licensing or historical coverage claim.

Main-thread collection, tape merging, snapshot packing and canvas painting remain. Queue waiting, many concurrent charts, gap-heavy calendars and slow devices can still increase latency. Worker cancellation discards a running job's callback; it does not preempt that job's CPU work shared with other studies. Complete exchange archives, recorded classified Replay, full TradingView/Vela parity and the separate intermittent older-candle issue remain open.
