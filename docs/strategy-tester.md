# Strategy tester

The bottom panel runs Pine v5/v6 `strategy()` scripts in the PineTS 0.13.0 broker emulator, with a reproducible local extension for lower-timeframe order execution. The local implementation is a functional historical tester; complete TradingView strategy-report and deep-testing parity remains open.

## Workflow

1. Open **Strategy tester**. Select EMA crossover, RSI mean reversion or Donchian breakout, or import/paste an available strategy source using **Strategy source code**. The included examples are original Affentrader scripts.
2. Use **Strategy inputs** to scan the real Pine input schema in a worker. Set inputs by their stable runtime IDs. Imported libraries resolve through the workspace's registered Pine libraries, including transitive dependencies.
3. Set initial capital, order size, commission model, slippage, pyramiding, margins and fill timing under **Strategy properties**. These values override the source declaration. Accounting uses the actual provider currency: Binance quote currency, Hyperliquid USDC, or Yahoo metadata (including EUR and GBp pence). There is no hidden conversion between currencies. Optional point-value, tick-size and quantity-step overrides are recorded in the report; zero uses provider rules or disclosed estimates.
4. Choose a maximum of 100–20,000 bars and optional UTC bounds. The end is exclusive. The active symbol selects Binance, Hyperliquid or Yahoo history. Binance custom time intervals use the shared source-planning/resampling pipeline; Hyperliquid supplies at most its latest 5,000 native candles, and Yahoo retains its provider-specific history limits. Data is deduplicated and OHLCV-validated. A provider failure is an error; it never silently substitutes simulated history.
5. **Run backtest** freezes the document, inputs, execution settings, market and history. The worker continues when another bottom tab is selected. **Cancel** aborts history requests and terminates the worker. A later run cannot receive an earlier worker's result.
6. Inspect the equity / bar-close drawdown curves, optional buy-and-hold benchmark, all/long/short performance, open positions and paginated trade list. The result keeps its own symbol, interval, source, dates and settings. Changing the current setup marks the previous result as stale until a new run completes.
7. Export trades/equity as CSV or the complete report as JSON. The report includes source provenance and original strategy document. The strategy source and settings persist in LocalStorage and validated workspace backups; result datasets are session-only and are recomputed after reload.

## Calculation boundaries

- The broker emulator handles entry/exit/reversal, market, stop, limit and stop-limit orders. Default market orders are evaluated at a completed bar and can first fill at the next available tick, usually the following open. Same-close fills require the explicit property.
- Commission applies on both legs. Percent, cash per order and cash per contract are available. Binance uses its actual `PRICE_FILTER` and `LOT_SIZE`. Hyperliquid uses exchange quantity decimals and a fixed price tick derived at the metadata snapshot price; historical variable precision is disclosed. Yahoo tick and quantity steps are estimates unless explicitly overridden. Yahoo futures require an explicit contract point value. The runtime uses that multiplier in both sizing and P&L, and percentage returns divide by the matching contract notional.
- The runtime receives the actual provider symbol, type, timezone and accounting currency through a public `Indicator.getRuntimePropOverrides()` adapter. USDC and GBp are retained as units rather than converted or relabeled USD/GBP. All report views, saved comparisons and CSV exports retain the currency and point value. Choosing a different account currency with historical FX conversion remains outstanding.
- Standard OHLCV always supplies execution prices, independently of the visual chart style. With **Use bar magnifier** disabled, the native historical four-price path is inferred. When enabled, independently recorded lower candles supply the broker path during order execution. This changes fills, fees, P&L and excursions in the actual run; it is separate from the retrospective audit.
- Net strategy P&L is the runtime's value, including incurred entry fees on still-open positions. Closed-trade statistics sum closed net trade P&L. Open positions remain separate and are marked to the final completed close. They are not force-closed to create additional closed trades.
- Runtime maximum equity drawdown includes the emulator's intrabar path. The drawdown curve is calculated from sampled bar-close equity; it is labeled separately and need not reach the intrabar maximum.
- The equity curve comes from `strategy.equity` sampled during the actual script run. Buy-and-hold invests the initial capital at the first loaded open and marks it at each close, without fees. It is a clearly defined comparison, not the runtime's first-entry benchmark.
- Sharpe and Sortino are the installed runtime's monthly-return ratios. The interface shows an unavailable value if fewer than two monthly equity observations exist.
- Pine `request.security()` secondary series use the same frozen end boundary and chosen data source, with provider-specific depth limits. Custom time intervals include seconds, minutes, hours, days, weeks and calendar months when their provider has a source. Tick-event strategy datasets are not implemented and are rejected explicitly. Missing secondary data fails; notices propagate to the report. Arbitrary script lookahead behavior remains governed by its Pine source and PineTS compatibility.
- Yahoo backtests preserve provider timestamps for session/date logic. Session gaps are not fabricated. Daily and larger periods are conservatively considered complete only after the whole calendar period; `time_close` is a calendar boundary and does not model early closes or exact exchange session ends. Extended hours and dividend adjustment are explicit settings. Equity analytics annualize Yahoo bar returns from the observed bar frequency instead of assuming 24/7 trading.
- Flat zero-volume stock/ETF rows are omitted as non-traded provider padding and counted in a notice. Zero-volume forex/index rows remain valid; they are not removed merely because their venue has no centralized volume.
- Hyperliquid's linear perpetual P&L is reported in USDC; historical funding, borrow costs and exchange liquidation rules are not modeled. A retrospective intrabar audit can inspect finer candles but does not recompute order fills.
- The selected loaded window supplies indicator warm-up. Earlier history is not silently included as a hidden trading period. A start date outside available history or the 20,000-bar limit produces a notice with the actual first candle. Gaps are disclosed and are never filled with invented exchange bars.
- Synthetic mode is explicitly selected, labeled in every report and included in exports. Its P&L is a simulation result, not evidence of historical exchange performance.

## Bar magnifier

Enable **Use bar magnifier** in Strategy properties. Choose `auto` or a finer divisible interval such as `1m` or `10s`. The same provider, symbol, source, adjustment settings and frozen test boundary supply up to 200,000 lower candles. Network errors fail the run. A history limit can leave older chart candles uncovered; their native parent OHLC path remains active, and the header, Properties, JSON, CSV and saved comparison identify coverage and fallback counts. A run with no verified coverage fails explicitly. Independently generated synthetic parent candles cannot supply recorded intrabars; magnification requires exchange history.

Coverage requires contiguous, complete lower candles within the parent interval, matching its open, high, low and close on the broker tick grid. Missing candles, session padding and inconsistent provider aggregates cause that entire parent candle to fall back. Exact Yahoo daily session ends are unavailable, so daily/weekly Yahoo coverage can be absent even when some intraday bars exist. Intraday Yahoo and continuous crypto intervals can use complete coverage. No lower candle crossing a parent boundary is consumed, and no future candle supplies a historical fill.

`auto` follows the scale of TradingView's published interval mapping, but selects a provider-supported divisor to avoid boundary crossing (for example 15m uses 1m rather than 2m). Unsupported seconds on Yahoo/Hyperliquid and a chart already at the finest resolution fail explicitly. Providers can retain far fewer than 200,000 intrabars.

The extension walks each lower candle's open, nearer extreme, farther extreme and close through the existing PineTS order engine. Equal-distance extremes retain PineTS's high-first tie rule. A jump from one lower close to the next open is a gap: eligible stops/markets fill at the available open rather than at an invented intervening price. Native sizing, fees, tick slippage, OCA, protective exits, stop-limit state, trailing state and margin/risk rules remain in that engine. The complete path also supplies native trade run-up/drawdown and equity excursions.

Pine indicators still consume the original parent series. The normal script executes once per parent bar. An explicit `calc_on_order_fills` declaration retains PineTS's segment-level recalculation and variable/plot rollback behavior. Fill times and bar indices retain parent-bar timestamps; lower candles still assume an OHLC path rather than reconstructing every trade. This is not tick-event execution or a claim of identical TradingView broker behavior.

The runtime is generated locally by `node scripts/build-strategy-runtime.mjs`, which also runs before `pnpm dev`, `pnpm build`, `pnpm typecheck` and `pnpm test`. It reconstructs complete upstream TypeScript from the pinned package's source map, applies checked modifications in `scripts/pinets-magnifier-patch.mjs`, bundles with legacy decorator semantics, and retains source and license in `.generated/`. An unexpected package version or patch location fails the build. `node_modules` remains unchanged. See `THIRD_PARTY_NOTICES.md` for attribution.

Remaining strategy parity work includes tick-event testing, exact exchange session closes, account-currency conversion, funding/liquidation models, deeper history beyond provider caps and optimization. Existing analytics, report comparison and trade-to-chart links do not prove complete TradingView equivalence. No orders are transmitted to an exchange.

Reference behavior: [TradingView strategies and broker emulator](https://www.tradingview.com/pine-script-docs/concepts/strategies/). Runtime authority: installed `pinets` 0.13.0 declarations and execution tests.

Interval reference: [TradingView Bar Magnifier](https://www.tradingview.com/support/solutions/43000669285-what-is-bar-magnifier-backtesting-mode/), inspected 2026-10-24. Local divisible-interval selection and coverage checks are explicit implementation choices.

Hyperliquid assumptions: [contract specifications](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/contract-specifications), [tick and lot sizes](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size). The fixed-tick limitation is an implementation boundary, not a claim that the exchange always uses that tick.
