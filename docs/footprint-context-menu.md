# Footprint context quick controls

Right-clicking a displayed Footprint row now opens the four quick controls described by the official Footprint reference: **Stat table**, **Average trade size**, **Visible range profile**, and **Footprint Settings**. Reference: https://docs.luxalgo.com/platform/charts/order-flow/footprint (inspected 2026-11-04).

The first two actions use the clicked instance's settings and show its name as a menu hint. They do not follow the data-window selection or re-target when the pointer moves onto the menu. This includes the aggregate Visible range profile, whose actions write its `vr*` settings. The visible-range switch controls the chart's aggregate profile. Settings opens the Footprint family or the Visible range subsection for a range hit. Menu checkmarks reflect the values at opening; selecting a command closes the menu. Off-row clicks keep the chart's normal context menu.

The renderer publishes token-owned menu frames alongside its actual hover geometry. Frames clear before each paint and on teardown; both primary and secondary chart hosts install and remove the listener. Filtered/unloaded cells and unfinished Replay candles are excluded. Before opening and again before applying, the menu checks the current market, timeframe, epoch, archive/source stamp, Replay boundary, renderer style, target instance and relevant settings. Ordinary live quantity changes are allowed. Changed settings/source or a replaced renderer cannot apply a stale toggle. Edits use the native configuration/series-preference persistence seam, preserving unrelated and disabled-instance settings.

- Seven cases in `tests/footprint-menu.test.ts`: official item/checkmark contract, independent root/secondary/range actions and disabled settings, live-versus-stale scope/Replay/settings checks, real binding event/capture and native config write, off-row fallback, stale producer/settings/style rejection, correct settings family and token/listener cleanup.
- Targeted tests: **38 passed across three files**. Complete suite: **2,240 tests in 206 files passed** (`artifacts/footprint-menu-tests.log`). Standalone TypeScript and production build passed (`artifacts/footprint-menu-build.log`).
- Initial native integration caught an incorrect active-style field assumption. The final guard and regression fixture use the SDK's exported `series.style` configuration field; the public construction option `priceStyle` is not the shape of `renderer.getConfig()`.
- Complete app on isolated loopback port 3001 with ephemeral test authentication: an actual Binance BTCUSDT 1m Visible-range row opened all four native menu items with checked states and target hints. The range Average action switched its own mean sizing off; Settings opened its subsection. The range Stat-table action remained enabled after reload, and the visible-profile action hid the aggregate. A subsequent actual Footprint 2 row opened a menu naming Footprint 2; its Average action remained enabled after reload while Footprint 1 stayed disabled. At 414 x 720 the menu stayed within the viewport and Escape closed it. Final console errors were empty. Screenshots: `artifacts/footprint-menu-range.png`, `footprint-menu-instance.png`, `footprint-menu-reload.png`, `footprint-menu-mobile.png`. No real site credential was read or changed.
