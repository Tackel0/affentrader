# Observed alert transitions and confirmed bars

The browser and local server now use `stepRule()` in `lib/alerts/runtime.ts`. Its per-rule/per-scope state contains the last valid quote fields, their observation time and source, the held condition state, the last firing time and the last evaluated candle boundary. Stored samples contain only finite numbers. Older server edge records remain readable and acquire observation samples on their next evaluation.

Previously the server gave each quote `previous = current`, which made actual quote crossing conditions impossible. The browser additionally discarded updates within a one-second throttle. Both paths now compare delivered observations. Price, reported base volume and range fields have independent previous values; moving lines use their value at the preceding observation's time. A crossing reaches the threshold from strictly below/above, consistent with the basic price-alert engine; leaving an exactly touched threshold is not another crossing.

Crossings and entering/exiting bands are events. Consecutive up/down events can both fire even when the combined boolean was true on the preceding observation. Legacy ordinary greater/less/inside/outside conditions retain false-to-true behavior; explicitly selected trigger modes apply the scheduling gates described in [alert scheduling](alert-scheduling.md). Cooldown applies after the first firing and does not retrospectively emit a suppressed crossing. A one-shot watchlist rule tracks each symbol independently and finishes after every current member has fired. This corrects the earlier first-match behavior. Creation, edits, resume and source changes establish a new baseline. Missing operands preserve an established edge; a newly created rule waits for its first valid baseline.

The browser dispatch index includes the scope and every explicit leaf market. Quote-only rules consume quote delivery; candle-dependent rules consume the trade callback after candle aggregation. The same trade therefore cannot evaluate a technical study before its candle update and suppress its subsequent evaluation. Distinct received prices sharing a millisecond are processed. Source restarts invalidate samples and history preparation, preserving cooldown timestamps. History preparation has four concurrent jobs and retries empty/failed series. Existing capacity limits remain: 40 candle-dependent watchlist symbols in the browser, and at most 60 loaded series in one server pass.

Close rules require actual candle history even when their operand is quote price. The cadence is the smallest condition interval. Only candles ending by the evaluation boundary are included, including a quiet market's final already-closed candle. The reported price and line evaluation time come from that closed candle, so a later live quote cannot satisfy a close condition. A persisted boundary prevents repeated evaluation of the same close across polls or restart. Provider quote metrics without a matching historical snapshot remain unavailable; use candle price/volume fields for confirmed candle values. Exact exchange session-close calendars remain outstanding, especially for Yahoo daily/session data.

The local server serializes evaluation passes. Event creation, delivery scheduling, observation updates and one-shot status changes commit in one atomic JSON-store update. A rule edited/paused/deleted during an in-flight market request is checked again before commit. Push is attempted only after a committed event. This establishes local single-process consistency; it is not a distributed exactly-once delivery guarantee.

Server observations remain polled, normally every 15 seconds, and upstream/cache freshness can be coarser. A round trip between observations cannot be reconstructed from two equal endpoint prices. Live-only quote metrics cannot be recovered at an earlier candle close. Explicit once-per-bar, once-per-close and once-per-minute modes, expiration and dynamic watchlist membership are implemented; see [alert scheduling](alert-scheduling.md). Absolute and percentage source movements now use actual N-bar references with deeper history requests; their [calculation and fidelity limits](alert-movement.md) are explicit. Full-universe candle alert capacity and hosted continuity remain open parity work.
