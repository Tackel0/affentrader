# Position protection

Open positions have a **TP/SL** action in the chart legend, Positions table and DOM. It opens **Protect position**, where one to four exit levels can be configured with independent quantities. A single regular level may contain only TP or SL; multiple levels require both prices in every pair. Removing every row and saving clears working protection while retaining the position.

TradingView's [position bracket reference](https://www.tradingview.com/support/solutions/43000754954-position-brackets/), [bracket API documentation](https://www.tradingview.com/charting-library-docs/latest/trading_terminal/trading-concepts/brackets/) and [multiple-level help](https://www.tradingview.com/support/solutions/43000772334-multiple-take-profit-and-stop-loss-levels/) were checked 2026-10-26. The documented four-level Paper Trading interaction and independent paired exit quantities inform this implementation. Complete broker/service equivalence remains unproven.

The dialog displays current position size, last price and configured coverage. Saving replaces all working same-symbol reduce-only exits, not just the pairs created by the original entry. It states that replacement count explicitly. Entry orders and other markets remain unchanged. Existing paired groups are recovered without merging independent groups; unsupported configurations require reviewing an explicit replacement. An unchanged equivalent configuration retains order identity and performs no account write.

Validation happens before replacing any order. Quantities must be positive, representable and sum to no more than the current exposure, allowing only floating-point rounding tolerance. Up to four levels are accepted. TP must lie beyond the current market, taking a fresh matching executable side into account; SL must lie on the other side of current last. This uses current observations rather than entry price, so a stop may lock in part of an unrealized profit. New protection does not immediately execute. Marketable changes remain possible through the separate working-order modification flow; this distinction is local behavior, not claimed native equivalence. Missing quotes reject new price levels; clearing protection needs no quote.

Each accepted level creates its own OCO group. Executing or canceling one leg cancels only its sibling. A filled partial exit retains other pairs for the remaining position. All exits are reduce-only: the broker rechecks remaining exposure when executing, preventing a reverse position from oversized stale protection. Other existing position close/reversal policies still apply. No depth consumption, liquidity-dependent partial fills, reservation system or exchange routing is added by this feature.

The review freezes symbol, account mode/feed generation, position size, average entry, opening time and realized P&L, plus a fingerprint of all working protective identities, revisions, prices, quantities and groups. These are rechecked after loading the latest account inside the shared write lock. A changed position or protective order requires reopening. A storage failure rolls back the entire replacement. Replay protection uses its local account and historical cursor clock. Working orders receive that creation time/source, so earlier queued live observations cannot fill them retroactively.

Multi-level exits on new entry tickets and pending entry orders are now implemented separately; see [entry-order exit levels](entry-exit-levels.md). Native preset integration, every mobile/satellite layout, continuous hosted/live-browser matching and exact exchange/broker semantics remain open. This manager operates on an already open local paper position. Production evidence and limits are recorded in `artifacts/verification.md`; pure broker and actual-store tests cover validation, partial OCO execution, concurrent edits, storage failure and Replay separation.
