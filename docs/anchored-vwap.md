# Anchored VWAP construction and alert consistency

The native Vela Anchored VWAP drawing now uses the same volume-weighted HLC3 calculation as linked drawing alerts. The installed 0.9.0 implementation previously substituted equal weights when the complete source had no volume and computed variance as E[p²]−E[p]². This could produce an unweighted curve under a VWAP name, change a zero-volume historical prefix when future volume appeared, and lose small deviations on a large price base.

`lib/orderflow/anchoredVwap.ts` implements weighted population deviation with a normalized Welford recurrence in standard-deviation space. It avoids squared-price overflow as well as subtractive cancellation. Leading bars without volume produce no samples; later zero-volume bars carry the last weighted state. Negative/nonfinite quantities, invalid selected HLCV, duplicate/out-of-order selected times, missing anchor coverage, nonrepresentable bands and more than 50,000 selected bars fail closed. Alert cutoffs exclude future bars. Loaded bars can still contain provider/session gaps: this is a bar-volume HLC3 approximation, not execution-level VWAP or proof of complete history.

`lib/drawings/anchoredVwapPlugin.ts` adapts the actual registered native factory. Native anchors, geometry, hit testing, settings, visibility, serialization, undo and drawing management remain in use. Numeric snapshots catch historical in-place revisions and immutable live replacements. Failed calculations clear the cached price/time extents; runtime samples and notices are not persisted. Caches are limited to 64 drawings and 250,000 retained source-bar slots.

The pinned five-bundle painter adapter in `scripts/patch-vela-anchored-vwap.mjs` displays HLC3 source, loaded count and volume, or the specific unavailable reason. It validates Vela's version/dispatch anchors, replaces package directory entries rather than modifying shared package hardlinks, and is idempotent. Captions wrap on narrow charts and keep space for native attribution.

The Anchored VWAP observation key includes the algorithm version. Existing alert subscriptions retain their schedule and fire history, but the first observation with the new calculation establishes a baseline rather than firing a crossing created by the upgrade. Subsequent real price crossings still trigger. Geometry persistence remains compatible.
