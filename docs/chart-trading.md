# Chart trading controls

The chart legend now contains red Sell and blue Buy buttons with the executable bid/ask when a fresh matching book exists. Without depth they explicitly show LAST or BAR instead of inventing a spread. Empty-price controls are disabled. This follows the public [TradingView buy/sell panel description](https://www.tradingview.com/blog/en/explaining-the-new-buy-sell-button-style-19793/) and [chart configuration help](https://www.tradingview.com/support/solutions/43000748166-how-to-configure-your-supercharts/), checked 2026-10-26; complete current desktop/mobile visual equivalence has not been established.

The default click opens a fresh market ticket for that side and symbol. Quantity is retained; stale limit/stop prices, brackets and reduce-only are cleared. The user can configure the order before submitting. Clicking an inactive chart first activates its own cell; another chart cannot consume the active cell's historical Replay account.

Chart settings → Trading contains Buy/Sell buttons and Instant paper order placement. The settings are shared across this window's chart cells and persist across reloads and workspace export/import. Instant placement starts disabled. When enabled, a quantity field appears between the buttons. A click submits a market paper order using that quantity and the existing serialized command/broker path; it does not inherit hidden protective or limit-order fields. A busy latch prevents a second click in the same component while its command is pending. Success and rejection notifications identify Paper execution. No live broker order is sent.

Replay uses its separate local account and historical clock/price model. Inactive-cell controls are disabled during another chart's Replay. Feed/context changes continue to fence queued commands through the paper command path. Quotes, depth freshness, slippage, fills and limitations are described in [paper trading](paper-trading.md).

Native settings and indicator dialogs mount on a shared viewport-sized host so a small chart cell or open bottom panel cannot clip them. The host adds switch labels and dialog/close accessibility labels to the renderer's existing controls; it does not replace the native configuration model. Core native display settings remain managed by Vela. Trading preferences and the chart timezone are included in the app's workspace serializer. They are window-wide preferences, not independently stored per named cell.

`chart-trading.test.ts` exercises the actual stores and serialized broker: default ticket staging, stale-field removal, actual instant ask execution, invalid quantity/context rejection, satellite activation, Replay separation, strict import validation and backup timezone/preferences. Browser evidence and the precise verified viewport/layout scope are recorded in `artifacts/verification.md`. Full broker connectivity, exact native order semantics, every TradingView chart-trading option and complete Premium parity remain open.
