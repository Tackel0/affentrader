# Replay exit and recent-view settlement — 2026-10-28

Vela0.9.0 stops Replay synchronously but resumes live data and starts its gap healer asynchronously. Its public historyComplete() promise describes the current initial-history cycle; it does not cover that later loadRange. Previously Reset awaited only historyComplete(), so it could calculate a range before the native healer applied newly recovered candles. The preceding Footprint audit observed that a second Reset after recovery was sometimes required. This continuation's fast-fetch baseline succeeded, so the baseline screenshot does not itself reproduce the delayed failure.

lib/chart/feedSettlement.ts wraps the primary chart's native feed. It tracks load/loadRange/progressive requests by symbol/timeframe while retaining source receivers, capability absence, live subscriptions, original promises and original rejection behavior. Its settlement waits for pending matching requests and native promise continuations, including another matching request started during completion. Other markets do not block navigation. Disposal releases waits without pretending to cancel an underlying network request.

lib/chart/recentNavigation.ts awaits native initial history, then the chart-local live settlement, before reading the latest series and choosing a window. Replay resets instead retain the revealed-prefix cutoff and do not wait for live repair. The existing Footprint padding stays applied. Empty history produces a diagnostic rather than an invented time range.

hooks/useVelaChart.ts uses that path for Reset and for replay:end reasons stopped/finished. Market-driven Replay endings do not force a recent view. Navigation serial, chart instance, active owner, market/timeframe, market revision, Replay revision and feed epoch fence stale results. Loading ownership is cleared on the next navigation or Replay entry, and completion affects only a still-current request. No native package patch was added.
