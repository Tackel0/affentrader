# Volume Bubbles market price precision

Reference: https://docs.luxalgo.com/platform/charts/order-flow/volume-bubbles, inspected 2026-11-04. Manual rows are documented as Ticks per row (default 8), alongside view-adaptive Auto rows.

`priceGridMetadata.ts` now reads public Binance spot `PRICE_FILTER.tickSize`, Kraken `AssetPairs.tick_size`, and Hyperliquid perpetual `szDecimals`. Binance's market-data-only exchangeInfo endpoint is documented at https://github.com/binance/binance-spot-api-docs/blob/master/faqs/market_data_only.md. Hyperliquid's price precision rule is documented at https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size: at most five significant figures, limited by 6 minus size decimals, with integer prices always allowed. Hyperliquid therefore resolves precision at the observed chart price; it is not advertised as a fixed exchange-wide tick. Missing/corrupt raw Hyperliquid precision is flagged separately instead of treating the old numeric zero fallback as verified metadata.

New Bubble instances default to `tickSize: 0`, labeled **Price tick override (0 = market)**. A positive explicitly stored value continues to override metadata. Manual row steps multiply the selected price tick by Ticks per row through canonical decimal-grid arithmetic. Auto uses the same selected base grid and adapts the multiplier to the price view. Simulation uses an explicitly labeled simulated display estimate; it does not claim exchange precision. Sources without verified execution-grid metadata require an override. No quote-decimal heuristic supplies an exchange tick.

The injected native loader shares requests across instances, caches at most 128 market entries for five minutes, and backs off errors for 30 seconds. The native study refreshes metadata, retains its collected executions during waiting/failure, and fences obsolete asynchronous completions after stop, suspension and market replacement. A late metadata result cannot overwrite a current explicit override. Status notices identify the selected tick and its source. Replay uses the current precision metadata and explicitly discloses that historical rule changes are not reconstructed; an override remains available.
