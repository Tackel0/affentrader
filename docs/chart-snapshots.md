# Chart snapshots

The camera button and toolbar overflow action capture the visible chart layout into a frozen preview when multiple cells are displayed, or the active chart when only one is visible. **Active chart** and **Visible layout** explicitly make a new capture of the chosen scope. **Download PNG** downloads that preview's exact image; closing the dialog discards its in-memory image. Later price, viewport or order changes do not alter an existing preview. Capture failures show an error instead of offering an empty download.

Mounted primary and satellite renderers register independently and unregister during teardown. Layout capture requires one ready renderer for every visible cell, rejecting loading/error cells instead of silently omitting them. A maximized cell exports only what is visible. The composite preserves measured cell positions, gaps and rows. It fits each native canvas within its original body rectangle without stretching, adds one header per cell and a common UTC capture-time footer. Each header prioritizes source, symbol and interval before the longer market title. Mixed live/Replay or synthetic inputs retain their own labels; the dialog describes different source labels as **Mixed sources**. A synchronous browser pass is not a guarantee of synchronized exchange observation times across feeds.

Capture uses Vela's synchronous `screenshotCanvas()` composite, which refreshes its native canvases before reading them. Working-order labels now have a canvas counterpart in the dedicated order layer, so their quantity/price, color and cancel affordance appear in the PNG as well as their projected lines. The interactive DOM buttons remain responsible for pointer/keyboard handling. Label packing and width constraints share the same chart coordinates, including separate pre-trigger stop-limit legs. Exported pixels have no interactive actions.

An added header records the input source, chart title/venue, interval and UTC capture time. It distinguishes market feed, delayed market feed, simulation, Replay, synthetic Replay and unavailable lineage; source text takes precedence in a narrow header. Capture time is the image's creation time, not a guarantee that every underlying quote is fresh. Replay's historical cursor remains part of the chart content; UTC capture time does not replace it. Unknown source lineage is not inferred from the current feed selector.

An individual chart retains its native physical pixel size. Its header uses the ratio of native pixels to measured chart CSS width, with a bounded fallback when a measurement is missing. Layouts use a common bounded pixel ratio derived from their mounted canvases; aspect-ratio differences are letterboxed. Metadata and labels are ellipsized within available width. The individual-chart filename sanitizes Windows-reserved characters in symbol/source names; layouts use a chart-count filename. Images remain out of persisted chart preferences and workspace backups.

This captures selected chart plots and native layers, rather than the whole application window: the watchlist and trading table are outside the image. Vela's native DOM-legend rasterization remains best effort. Exact raster/DOM font equivalence on every browser, mobile/device validation and complete TradingView snapshot/sharing service parity remain unverified or outstanding. Nothing is uploaded or published by taking a snapshot.

`chart-snapshot.test.ts` covers compositing, source metadata, DPI scaling, frozen image values, narrow headers, filenames, empty canvases, missing contexts, encoding failures and raster order labels. An actual chart-store/backup test verifies that snapshot image bytes are excluded from durable preferences and backups. Production browser and inspected PNG evidence are recorded in `artifacts/verification.md`.

`layout-snapshot.test.ts` checks multi-row/eight-cell geometry, viewport coordinate normalization, real canvas composition, aspect-ratio fitting, source labels, missing/loading renderers, hidden cells and registration replacement/cleanup safety.
