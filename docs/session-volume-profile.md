# Session Volume Profile — 2026-10-28

The former right-edge histogram summed only the current UTC date and exposed no native input schema. Session Volume Profile now groups retained classified executions by actual session boundaries and anchors each histogram to its session. It supports Buy/Sell, Total and Delta modes, value-area coloring, POC/VAH/VAL lines, independently visible labels, start/end placement and proportional width. Six colors and all profile controls are editable through separate Inputs/Style sections. Unrelated native studies retain their original source/line controls. The legend shows a compact price-grid/percentage/zone description rather than every cosmetic value.

`lib/orderflow/sessionCalendar.ts` is shared with TPO. IANA time zones, exchange/computer choices, opening minutes, wall-clock duration, overnight opening dates and weekday filtering use DST-aware boundaries. Ambiguous openings use the first occurrence; short-session ambiguous endings use the last occurrence. Full-day boundaries remain contiguous. Nonexistent boundaries roll forward to a valid minute within three hours. Calendar caches retain at most 400 dates and 20,000 timestamp assignments. This does not supply official exchange holidays or automatic pre-/post-market calendars. Existing TPO errors remain wrapped in their scoped diagnostic type.

`volumeProfileModel.ts` deduplicates execution IDs, rejects malformed/nonpositive quantities or prices, and keeps exchange/simulation data separate according to the latest valid source. It sums actual classified quantities into dense price rows, including empty price gaps. Session windows are opening-inclusive and ending-exclusive. Manual row sizes stay fixed; automatic rows derive from the full retained session range, independently of viewport and price-scale changes. POC ties choose the closest row to the profile midpoint, then the lower row. The VA expansion follows the currently published adjacent-row rule: prefer the larger neighboring volume, then the closest row to POC, then the upper row; stop before the next row would exceed the target. POC alone can exceed a small percentage. The POC tie rule is local and exact proprietary equivalence is unproven.

The public references are [Vela Pro order flow](https://velacharts.dev/pro/) and [TradingView volume-profile concepts](https://www.tradingview.com/support/solutions/43000502040-volume-profile-indicators-basic-concepts/), with [Session Volume Profile controls](https://www.tradingview.com/support/solutions/43000703072-session-volume-profile/). TradingView describes directional lower-candle volume; this implementation uses classified exchange executions for Buy/Sell. It does not relabel directional OHLC volume as aggression or import the closed Vela Pro engine.

The model rejects more than 2,000 dense rows in a session, 100,000 loaded rows, 100,000 input trades, indistinguishable price precision and overflowing quantities. It returns no partial calculation on failure. Settings can be corrected in the same dialog. The actual market service currently retains at most 5,000 trades per symbol, so that smaller source retention remains authoritative. The footer labels collected versus simulated data, retained trade count, first/last retained UTC timestamps, exclusions and partial history. These bounds describe the retained source, including observations outside a custom session; they do not establish complete session coverage. A cold reload starts collection again.

`volumeProfileIndicator.ts` mounts an empty native output to enter Vela's normal lifecycle, then publishes a stable SDK channel. Model/error caching avoids recomputing unchanged trade/settings revisions. Direct trade subscriptions coalesce bursts into 16 ms updates; each renderer then schedules its own canvas repaint. Trade-only changes do not repeatedly push SDK scene invalidations. Suspend/removal detach subscriptions, cancel timers, clear the channel and fence stale callbacks. Resume reads the newest retained trades. During Replay it paints an explicit unavailable notice and never projects today's executions into past sessions. Yahoo markets without classified trade data receive a source-specific diagnostic. Native layer registration and indicator inputs require no package patch.

`volumeProfileRenderer.ts` keeps true price projections on normal/inverted/logarithmic SDK axes. It stacks classified side quantities, or renders total/absolute delta widths, against the session's largest row. POC/VA lines stay at their actual grid prices; nearby text labels separate vertically to remain readable. Small profiles remain small when only a narrow range of trades has been collected. The footer has an opaque background for legibility. Session-start anchors can leave the viewport when panning; the model and source history do not change with that pan. Right-side developing profiles anchor at the last observed execution, while completed sessions anchor at their close. Width follows the elapsed session span.
