# TPO / Market Profile — 2026-10-28

The former purple letter-only chart is replaced by session-anchored blue value-area blocks, neutral outer blocks, a point-of-control line, value-area boundaries, an orange session-range bracket and optional actual OHLC candles. Split mode places each period in its chronological column; merged mode packs occupied periods on each price row. Letters hide when their cells are too small to read. The visual reference was the public Vela Pro image at https://velacharts.dev/images/vela/pro-tpo-interface.jpg, linked from https://velacharts.dev/pro/. This is an implementation through the public Vela SDK, not an import of the closed Pro engine or proof of pixel parity.

`lib/orderflow/tpoMath.ts` counts each time block once per price row, including dense empty rows between traded ranges. Period labels continue A–Z, a–z, A2–Z2 rather than wrapping ambiguously. POC ties choose the row closest to the profile midpoint, then the lower row. The value area grows contiguously from POC toward the adjacent row with the greater count; equal adjacent counts include both rows, so the requested percentage can be exceeded. These are explicit local rules, not a verified reconstruction of closed-source tuning.

`tpoModel.ts` assigns loaded bars to sessions independently of the visible viewport. Each session uses a fixed manual grid or an automatic grid based on its full loaded range. Session time zone, opening minute, wall-clock length, weekday filter, block length, price rows, percentage and display colors live in the native settings page. IANA dates honor DST: ambiguous openings use the first occurrence; short-session ambiguous endings use the last occurrence; full-day boundaries remain contiguous. Nonexistent boundaries roll forward to the first valid minute within three hours. Overnight sessions belong to their opening date. The weekday filter excludes Saturday/Sunday opening dates; it is not an exchange holiday calendar.

The renderer consumes only bars supplied by the chart, including its revealed Replay prefix. Reset frames up to three loaded sessions and returns through the existing live-feed settlement after Replay. A session can be partial when loaded history starts within it. Profiles are OHLC-derived: a bar contributes its complete high/low range to its time block. They do not prove tick-by-tick visits, execution order, Bid/Ask classification or historical traded volume. Bars must fit both block and session boundaries. Tick, coarse, non-dividing and boundary-crossing intervals produce an explicit diagnostic instead of an approximate profile.

Limits reject more than 2,000 dense rows, 200,000 occupied cells per profile, 2,000,000 row visits per profile or 1,000,000 occupied cells across loaded sessions. Invalid or indistinguishable numeric price grids also fail. Errors display no partial profile. The scoped Reset TPO settings action restores only that cell's TPO defaults. The result/error cache keys the native series identity, latest range, market, interval and settings; unchanged close/volume ticks and viewport redraws reuse models. Calendar assignments survive tail revisions. Native setBars replaces history identity, while updateBar changes the tail; mutating older bars in place is outside this cache contract.

Preferences persist per cell, layout and backup with legacy compatibility. `seriesBinding.ts` restores defaults when an older configuration has no TPO bag. The native settings patch merges only known TPO controls and preserves other chart-type settings. No additional Vela package patch was required.
